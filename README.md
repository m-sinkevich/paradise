```
paradise/                             ← корень репозитория
├── index.html                        ← стартовая страница со списком модулей
├── terminal.html                     ← терминал (бывший terminal_full_paradise.html)
├── fonts/
│   ├── Robtronika-4Bq8p.woff         ← положить свои файлы, имена — с точным регистром букв
│   └── Y224-pgj1O.woff
├── media/                            ← по желанию: картинки и аудио для контента
├── .nojekyll
├── .github/workflows/supabase-keepalive.yml
└── README.md
```

Что изменено в терминале по сравнению с `terminal_full_paradise.html`:
- модуль задаётся адресом `?module=КОД` и запоминается на этом компьютере. Без кода терминал пишет «МОДУЛЬ НЕ ВЫБРАН»;
- на планшетах и телефонах включается задняя камера (если её нет — любая доступная);
- текст записей журнала больше не интерпретируется как HTML;
- версия библиотеки Supabase зафиксирована (2.117.3), чтобы обновление не сломало терминал в игровой день.

## Публикация (один раз)

1. Репозиторий `paradise` уже есть: https://github.com/m-sinkevich/paradise (должен быть **Public**).
2. **Add file → Upload files** → перетащите всё содержимое папки `site`, включая папки `fonts` и `.github` → **Commit changes**.
   Если браузер не увидел скрытые `.github` и `.nojekyll` (на macOS файлы с точкой скрыты в Finder), создайте их вручную: **Add file → Create new file**, в поле имени введите путь `.github/workflows/supabase-keepalive.yml` и вставьте содержимое файла.
3. **Settings → Pages** → Source: **Deploy from a branch** → Branch **main**, папка **/ (root)** → **Save**.
4. **Settings → Actions → General** → *Workflow permissions* → **Read and write permissions** → **Save**. Без этого будильник не сможет обновлять файл-отметку (см. ниже).
5. Через 1–3 минуты откройте https://m-sinkevich.github.io/paradise/.

## Подготовка базы (один раз, SQL Editor в Supabase)

```sql
alter table content_items drop constraint if exists content_items_type_check;
alter table content_items add constraint content_items_type_check
  check (type in ('text','image','audio','video','event'));

alter table alerts add column if not exists excluded_module_ids uuid[] default '{}';

insert into storage.buckets (id, name, public)
values ('content-media', 'content-media', true)
on conflict (id) do update set public = true;

create policy "anon read content-media"   on storage.objects for select to anon using (bucket_id = 'content-media');
create policy "anon insert content-media" on storage.objects for insert to anon with check (bucket_id = 'content-media');
create policy "anon update content-media" on storage.objects for update to anon using (bucket_id = 'content-media');
```

Затем откройте **Database → Publications → supabase_realtime** и включите таблицы `alerts`, `modules`, `journal_entries`, `events`.

## Чтобы база не засыпала

Бесплатный проект Supabase ставится на паузу примерно после 7 дней без запросов. После этого и сайт, и терминалы пишут «база недоступна», пока проект не восстановят вручную.

### Автоматически: будильник в GitHub Actions

Файл `.github/workflows/supabase-keepalive.yml` уже в репозитории. Он:
- **каждые 3 дня** (в 09:17 по Тбилиси) делает маленький запрос к базе — читает одну строку из `modules`. Этого достаточно, чтобы проект считался активным;
- при ошибке повторяет запрос 3 раза. Если база так и не ответила, запуск помечается красным, и GitHub присылает письмо на почту аккаунта;
- раз в ~50 дней без коммитов сам обновляет файл `.github/keepalive.txt`. Иначе GitHub отключает расписание в публичных репозиториях после 60 дней без активности.

**Проверка после публикации:** вкладка **Actions** → *Supabase keepalive* → **Run workflow**. Через полминуты должна появиться зелёная галочка, а в логе — строка «База на связи».

**Включить письма о сбоях:** аватар → **Settings → Notifications → Actions** → отметьте *Email* и *Only notify for failed workflows*.

### Если проект всё-таки уснул

1. Откройте https://supabase.com/dashboard/project/yfogwbxxomuzbezgpqjm → кнопка **Restore project**. Восстановление занимает несколько минут.
2. В GitHub: **Actions** → *Supabase keepalive* → **Run workflow**, чтобы убедиться, что база снова отвечает.
3. Если в Actions висит жёлтая плашка о том, что сценарий отключён из-за неактивности, нажмите **Enable workflow**.

Бесплатный проект, простоявший на паузе очень долго (обычно больше 90 дней), может уже нельзя будет восстановить из панели. Поэтому перед длинным перерывом между играми делайте выгрузку таблиц в CSV.

### Вручную перед игрой

Накануне игрового дня откройте стартовую страницу. Если в шапке горит «SUPABASE · БАЗА НА СВЯЗИ», всё в порядке.

## Настройка терминала на компьютере модуля

1. Откройте https://m-sinkevich.github.io/paradise/ → у нужного модуля нажмите **Открыть терминал**. На планшете можно отсканировать QR со стартовой страницы, открытой на другом экране.
2. Нажмите «Авторизация» и разрешите камеру. Браузер запомнит разрешение.
3. Добавьте страницу в закладки. Полный экран — `F11`. Режим киоска:
   `chrome --kiosk "https://m-sinkevich.github.io/paradise/terminal.html?module=PARADISE"`
4. Отключите сон и заставку экрана.
5. Чтобы звук тревоги включался сам, без касания экрана, запускайте браузер так:
   `chrome --kiosk --autoplay-policy=no-user-gesture-required "https://m-sinkevich.github.io/paradise/terminal.html?module=PARADISE"`
   Без этого флага браузер включит звук только после первого касания экрана, о чём терминал напишет в баннере тревоги.

## Обновление

Загрузите изменённый файл через **Upload files** (он заменит старый). Через 1–3 минуты новая версия появится на сайте. На терминалах нажмите **Ctrl+Shift+R**. Во время игры сайт лучше не трогать: контент, персонажи и тревоги меняются через базу.

## ⚠ Безопасность

Ключ Supabase виден в коде страницы, а база разрешает анонимному пользователю всё. Любой человек, открывший сайт, технически может прочитать пароли персонажей и сюжет, а также изменить данные. Для LARP «на честность» этого достаточно, если не раздавать адрес за пределы игры. Перед каждой игрой делайте резервную выгрузку. Настоящая защита (вход мастера, ограничительные RLS-политики) — следующий этап, см. ТЗ v3, §15.


## Терминал мастера по публичной ссылке

`master.html` и `nfc.html` открываются по ссылкам выше и запрашивают пароль мастера.
Пароль в коде не хранится — только его хэш; после ввода браузер помнит доступ 12 часов (кнопка «Выйти ⏻» сбрасывает).
Чтобы сменить пароль, нужно пересчитать хэш (SALT/HASH в блоке «ДОСТУП ПО ПАРОЛЮ МАСТЕРА» обоих файлов).

Во вкладке «Метки NFC» есть блок **⚙ Настройки сканеров** — длительность сессии, реакция на метку без кнопки, типы меток и PIN служебного меню для всех телефонов сразу. Телефоны получают их при «ОБНОВИТЬ ⟳». Нужна таблица `scan_settings` (см. `supabase.sql` в репозитории colony-scanner).

Пароль закрывает интерфейс от случайных посетителей, но ключ базы по-прежнему виден в коде страниц.
Не публикуйте ссылку на терминал мастера открыто; полноценная защита — вход через Supabase Auth (следующий этап).


## Угрозы

Вкладка **«Угрозы»** терминала мастера (раньше «События»). Готовые угрозы — по одной на каждую плашку терминала:

| Угроза | Плашка | Что происходит на терминале |
|---|---|---|
| Сейсмическая угроза | Сейсмо-скан | магнитуда растёт, экран трясётся, подземный гул |
| Биологическое заражение | Био-опасность | контаминация растёт, летят споры, щелчки дозиметра |
| Разгерметизация | Целостность модуля | прочность и давление падают, пробои, красная пульсация, шипение |
| Отказ жизнеобеспечения | Атмосфера модуля | O₂ падает, CO₂ растёт, экран «дышит» темнотой, писк монитора |
| Перегрузка энергосистемы | Энергосистема | нагрузка зашкаливает, экран мигает и проседает, гул и треск |
| Пылевая буря | Метеорология | ветер и мороз, частицы вокруг купола несутся быстрее, пыль, вой ветра |
| Потеря связи | Связь | потери пакетов, глитч плашек, помехи, белый шум |
| Запрос центра управления | Бортовой журнал | плашка журнала мигает, морзе; снимается записью в журнал |
| Простая тревога | — | только баннер и цвет фона |

При угрозе плашка выделяется, её показатели плавно уходят в опасные значения, фон всего терминала окрашивается
в цвет угрозы и пульсирует, играет встроенный звук (можно заменить своим файлом или выключить).
Над кнопками терминала — карточка с инструкцией, таймером обратного отсчёта (подпись редактируется) и заданием.
Терминал при этом не блокируется.

Настройки при запуске: сила 1–3, цвет, текст статуса и значение главного показателя, все модули или выбранные,
сейчас или по расписанию, длительность, таймер.

**Окончание угрозы:**
- мастер — «Снять везде» или ✕ у конкретного модуля в списке активных угроз (сценарий тогда не запускается);
- по времени — когда истекла длительность;
- игроки — после авторизации сканируют все QR-коды ремонта (каждый код может показать своё сообщение)
  или делают запись в бортовой журнал; угроза снимается только с их модуля.

**Сценарий:** «Затем запустить» — следующая угроза стартует в этом модуле через заданное число секунд после окончания
(по времени или устранением). Без сценария терминал возвращается в обычный режим.

**Свои угрозы:** настройте любой паттерн и нажмите «Сохранить как свою угрозу» — она появится в каталоге у всех мастеров
и может использоваться как шаг сценария.

Для работы нужно один раз выполнить `sql/threats.sql` в Supabase → SQL Editor.


## Карта полигона при угрозе

Карта — по желанию: в форме угрозы галочка **«Показать на терминале карту с точками»**. Когда она включена, открывается
редактор: клик по карте ставит точку (до 6), точку можно перетащить, колесо мыши и +/− — масштаб, перетаскивание пустого
места — сдвиг. У точки — тип, подпись и дополнительная информация.

На терминале карта открывается квадратом в центре между плашками (размер подстраивается под экран). Точки показываются
без подписей — только значок с анимацией; подпись, сектор и доп. информация всплывают при нажатии на точку.
Кнопки на карте: спутник, + и − (масштаб, карту можно двигать пальцем/мышью), ⛶ — во весь экран, ▾ — свернуть в кнопку «▣ КАРТА».
Типы точек различаются цветом и формой (читаются в ч/б): опасность — треугольник, сбор — круг, укрытие — квадрат,
цель — ромб, отметка — шестиугольник.

Карта построена по данным OpenStreetMap, кроны деревьев — по снимку, рельеф — горизонтали через 2 м (Copernicus DEM 30 м).
Файлы: `map/topo.json`, `map/hill.jpg`, `map/sat.jpg`, `map/polygon-map.js`.

## Снимки с камеры терминала и журнал действий

Нужно один раз выполнить `sql/camera.sql` в Supabase → SQL Editor.

- Вкладка «Модули» → у модуля кнопка **📷 Снимок**, или в окне модуля **«Сделать снимок»**. Терминал делает кадр
  (на его экране на секунду появляется «◉ ФОТОФИКСАЦИЯ»), снимок открывается у мастера через 2–5 секунд.
  Терминал должен быть открыт, а браузеру разрешён доступ к камере. Запросы старше 2 минут не выполняются.
- В окне модуля: **архив снимков** (нажатие — крупно) и **журнал действий терминала** с фильтром
  (угрозы, вход и выход, сканирование, бортовой журнал, снимки).
- Во вкладке «Модули» под модулем видны действующие на нём угрозы с кнопкой **✕ СНЯТЬ** (снимает только с этого модуля).

## Связь между модулями

Нужно один раз выполнить `sql/comms.sql`, затем `sql/channels_v2.sql` в Supabase → SQL Editor (оба можно повторно).

- **Канал — общий чат.** Участники — модули целиком и/или любые персонажи (сколько угодно). Канал «модуль ↔ модуль» —
  просто два модуля в участниках. Модуль-участник видит канал на своём терминале всегда; персонаж-участник —
  после входа на любом терминале (на терминале его модуля видно «есть личное»).
- **Мастер** (вкладка «Связь») видит все каналы и всю переписку, создаёт и настраивает каналы (участники, что можно
  отправлять, QR-код), пишет в любой канал **от любого имени** — поле «От кого», и по-прежнему пишет модулю или
  персонажу лично от центра управления.
- **Игроки создают каналы**: в окне персонажа галочки «Может создавать каналы связи» и «🕶 Хакер». На терминале модуля,
  куда у персонажа есть доступ: «Связь» → «+ Создать канал» → участники из всех модулей и персонажей.
- **Хакер** может сделать канал скрытым: он невидимый участник — остальные его не видят в списке и не знают, кто создал
  канал; писать может анонимно («Неизвестный источник»). Мастер видит всё, скрытые участники помечены 🕶.
- **QR-код канала** добавляет в участники модуль, где его отсканировали, или персонажа, который сканировал.
- На терминале — кнопка «Связь», плашка «✉ НОВЫХ СООБЩЕНИЙ» и короткий сигнал. Старые каналы переносятся автоматически.

## Контент: форматирование, варианты, печать QR

Нужен `sql/channels_v2.sql` (поле вариантов).

- **Текст контента понимает Markdown**: `**жирный**`, `*курсив*`, `# Заголовок`, `- список`, `1. список`, `> цитата`,
  `---` линия, `` `код` ``. В редакторе — «👁 Как увидит игрок».
- **Варианты для персонажей**: в объекте контента «+ Вариант для персонажей» — выбранные персонажи (вошедшие на
  терминале) видят свой текст вместо основного.
- **«⤓ Все QR в PDF»** во вкладке «Контент» — лист A4 по 12 кодов: QR, код, тип, модули и начало текста.

### Таблица и окно контента

Нужен `sql/content_v2.sql` (один раз, можно повторно).

- **Краткое описание** — видят только мастера: в таблице контента и на листе «Все QR в PDF».
- В строке таблицы: модули (или «все модули»), персонажи (или «все игроки»), кто открывал и кнопка
  «👁 просмотрено / ○ не просмотрено» — мастер переключает её одним нажатием. Терминал сам ставит «просмотрено»
  при первом открытии. Нажатие на строку открывает окно объекта; окно помещается на экран (две колонки).
- **Доступно персонажам** — если выбраны, остальные вошедшие видят «ДОСТУП ОГРАНИЧЕН». Ограничение по модулям
  теперь тоже действует на терминале.

### Сборные страницы, фильтры и цепочки

Нужен `sql/content_v3.sql` (один раз).

- **Страница из блоков**: текст (обычный / выделенный / тревожный), картинка, несколько картинок, видео, аудио, линия.
  Блоки двигаются ↑ ↓; «половина» — два блока подряд встают в ряд. Картинки на терминале открываются крупно по нажатию.
  Старые объекты (тип + текст + файл) открываются как страница из одного-двух блоков.
- **Фильтры** в таблице контента: по модулю и по игроку. **«⑂ Цепочки»** — дерево ветвлений от начала до конца,
  с номером шага; возврат по кругу помечен ↺.
- В «Ветвлении» у варианта — **«+ Новый объект»**: открывается полноценное окно нового объекта (с доступом родителя и
  условием «через выбор»), после сохранения он сам привязывается к варианту. Можно вкладывать сколько угодно глубоко.

### Персонажи

Плашки по модулям с иконкой модуля. Нажатие на персонажа раскрывает досье на один экран: фото, бейдж (показать / скачать),
данные и способности, легенда и вкладки **Сообщения** (отправленные и полученные, с прослушиванием голосовых),
**Журнал** (его записи в бортовом журнале) и **Контент** (что он открывал — нажатие показывает, как видел игрок).

## Потеря связи при тишине в журнале

Автоматически, на терминале модуля: за 10 минут до конца «таймера тишины журнала» (настройки модуля) — предупреждение
ИИ, по истечении — угроза «Потеря связи» на этом модуле. Снимается записью в бортовой журнал или мастером. Мастер видит её
в активных угрозах.

## Каталог персонажей и бейджи

Нужно один раз выполнить `sql/catalog.sql` в Supabase → SQL Editor (можно повторно). Он добавляет персонажам поля
каталога (фото, «кратко», легенда, модуль, картинка бейджа), заполняет 16 персонажей и ставит им **QR-коды как на напечатанных бейджах**
(персонажи ищутся по имени; недостающие создаются).

- **Каталог** `catalog.html` — для игроков, удобен на телефоне: модули, карточки с фото, поиск по имени, легенда по нажатию,
  кнопки «Правила» и «Лор» (тексты — `catalog/rules.md` и `catalog/lore.md`, правятся прямо в репозитории).
  Ссылка на конкретного персонажа: `catalog.html#<id>`, на правила — `catalog.html#rules`.
- **Панель мастеров → Персонажи**: миниатюра фото, кнопка «🪪 Бейдж» (картинка бейджа), в окне персонажа — раздел
  «Каталог персонажей и бейдж»: фото (путь или загрузка), кратко, легенда, модуль, показ в каталоге.
- **Описание модуля** для каталога — в окне модуля → «Настройки модуля».
- **Вкладка «Модули»** — плитки модулей: связь, жители, угрозы, новые сообщения, лица жителей; нажатие раскрывает плитку
  (подробности, жители с бейджами, снимок, окно модуля, ссылка на терминал).
- **Бейджи**: `badges/badges_print.pdf` — A4 альбомный, 6 бейджей 70×85 мм на листе, печатать в масштабе 100 %.
  Перед печатью всей партии распечатайте пробный лист и проверьте коды 2–3 телефонами. Пересборка — `tools/badges/README.md`.
