## 1. Общее описание

Веб-приложение (HTML/JS/CSS, без сборки) — терминал в жилом модуле колонии. Работает в браузере на любом компьютере или планшете. Сеть из **5–6 терминалов**, до **20 игроков одновременно**. Панель мастера — отдельная страница. Общая база данных — Supabase (Postgres + Realtime + Storage), доступ через интернет. Интерфейс стилизован под HUD-панель станции: в центре — интерактивный 3D-купол (three.js), по бокам — восемь панелей телеметрии.

Состав файлов:
- `index.html` (ранее `terminal_full_paradise.html`) — терминал модуля;
- `fonts/` — локальные шрифты терминала;
- `terminal_admin_6_6.html` — панель мастера (рекомендуется не публиковать, см. §15).

## 3. Основной пользовательский сценарий

1. **Режим ожидания.** HUD с куполом и панелями виден всегда. В шапке — название модуля, часы (реальное время, год смещён на +172) и блок «Доступ закрыт» с кнопкой **«Авторизация»**.
2. Кнопка открывает **модальное окно сканера**: попап с анимацией масштабирования, камера включается сразу. Внутри — видео, рамка вокруг найденного QR, индикатор «поиск…» / «✓ считано», поле пароля и поле ручного ввода кода.
3. После успешного входа попап сворачивается со вспышкой подтверждения. В шапке появляются имя персонажа, его код и таймер сеанса. Внизу по центру появляется док:
   - **Скан инвентаря / QR** — тот же сканер, для объектов;
   - **Бортовой журнал** — модальное окно с полем записи и списком записей модуля;
   - **Завершить сеанс**.
4. Контент по QR выводится в модальном окне: текст (посимвольный вывод), изображение, аудио, видео. Возможны ветвления до 8 шагов с кнопкой «Назад».
5. Повторное сканирование объекта с `playback = once` даёт сообщение «ДОСТУП ЗАКРЫТ».

## 4. Сессия игрока

Настраивается на персонажа (`characters`):
- **`session_timeout_minutes`** — жёсткий таймер. Обратный отсчёт виден **в шапке**. По истечении — выход в режим ожидания. Без значения показывается «∞».
- **`inactivity_timeout_minutes`** — таймер бездействия, сбрасывается кликом, клавишей или касанием.
- Оба таймера опциональны и независимы.
- Вход блокируется, если `characters.active = false`.
- Завершение (`manual` / `timeout` / `inactivity`) пишется в `logs`.

Не реализовано: проверка `characters.module_access` при входе. Поле редактируется в админке, но терминал пускает персонажа на любой модуль.

## 5. Бортовой журнал и «тишина в эфире»

- Текстовая запись с привязкой к автору, модулю и времени. При записи обновляется `modules.last_journal_entry_at`.
- Панель «Бортовой журнал» в правой колонке HUD показывает реальное число записей модуля и «тишину в эфире» (минуты с последней записи). Обновление — раз в 60 с, отсчёт тишины — раз в 15 с.
- **Автотриггер тишины** (`SilenceWatcher`, проверка каждые 20 с): если журнал молчит дольше `modules.silence_timeout_minutes`, терминал сам показывает первый объект контента с `unlock_condition.type = 'silence_timeout'`, доступный этому модулю по `module_scope`. Срабатывает один раз за период тишины; новая запись сбрасывает этот флаг. ✅
- Не реализовано: realtime-подписка терминала на `journal_entries`. Записи с других терминалов видны после повторного открытия журнала.

## 6. Режим тревоги модуля

Баннер с красной диагональной штриховкой поверх всего интерфейса. Показывается **независимо от авторизации**. ✅

- Таблица `alerts`: на конкретный модуль (`target_type = 'module'`, `target_module_id`) или на все (`target_type = 'all'`).
- Запуск сразу или по расписанию (`starts_at`), окончание по `ends_at` или по `active = false`.
- **`excluded_module_ids`** — модули, с которых мастер снял глобальную тревогу, оставив её на остальных. ✅ (требует миграции, Прил. А)
- Терминал опрашивает тревоги каждые 15 с и подписан на realtime по `alerts`.
- Показывается самая свежая из подходящих тревог.

## 7. События от мастера

Мастер отправляет событие на модуль, группу или все модули: сирена, видео на весь экран, смена интерфейса, разблокировка контента. `interrupt_behavior`: `hard` прерывает сразу, `soft` ставит в очередь.

*Статус: не реализовано.* Таблица `events` есть. В админке тип контента `event` и поле прерывания редактируются, но отправки событий и их обработки на терминале нет. Контент с условием `master_event` пока всегда заблокирован с поясняющим сообщением. Этого не стоит воспринимать как ошибку: так сделано намеренно, чтобы не открыть сюжетный контент раньше времени.

## 8. Логика выдачи контента

```
content_item:
  id
  trigger_code            # код в QR (6 символов из генератора, без 0/O/1/I/L)
  chain_id, order_index   # в схеме есть, кодом не используются
  type: text | image | audio | video | event
  body                    # текст / подпись
  media_url, media_path   # URL (Storage или относительный путь media/...)
  playback: once | unlimited
  module_scope: uuid[]    # null = все модули
  unlock_condition: {
    type: always | after_timer | master_event | player_choice | silence_timeout
    timerMinutes / eventId
  }
  choice_options: [{ id, label, nextContentId }]   # до 8 вариантов
  requires_previous: uuid[]
  interrupt_behavior: hard | soft                 # для type=event
```

| Механика | Статус | Как работает |
|---|---|---|
| `always` | ✅ | Открывается сразу |
| `player_choice` | ✅ | Доступ через кнопку выбора в другом объекте |
| `after_timer` | ✅ | Таймер считается от **первой попытки** открыть объект (`character_progress.first_opened_at`), до истечения выводится оставшееся время |
| `silence_timeout` | ✅ | Только автоматически (§5); при сканировании — отказ |
| `master_event` | ⛔ блокирует | Ждёт реализации §7 |
| `once` / `unlimited` | ✅ | По `character_progress.play_count` на персонажа |
| Ветвление | ✅ | До 8 шагов, кнопка «Назад» без повторного расхода `once`. Выбор **не одноразовый** |
| `requires_previous` | ❌ | Редактируется в админке, терминал не проверяет |
| `module_scope` при скане | ❌ | Учитывается только для `silence_timeout`; сканом объект открывается на любом модуле |
| `chain_id` / `order_index` | ❌ | Не используются, цепочки строятся через `choice_options` |
| `modules.current_content_id` | ❌ | Админка показывает его и умеет сбрасывать, но терминал его не записывает |

## 9. Панель мастера — ✅ реализована (`terminal_admin_6_6.html`)

Шапка: статус подключения, счётчики модулей, активных тревог, шаблонов и персонажей.

**Вкладка «События»**
- Активные тревоги (идёт / запланирована / истекла), кнопка «Снять».
- Обзор модулей: онлайн, если `last_seen_at` < 2 мин. Терминал шлёт пульс каждые 45 с и при возврате вкладки в фокус.
- Шаблоны тревог (хранятся в `localStorage` браузера мастера, на другой ПК не переносятся).
- Запуск тревоги: метка, цель (все / модуль), сейчас или по расписанию, длительность 5–60 мин или без ограничения.
- Тестовая тревога на 2 минуты на всех модулях.

**Вкладка «Контент»** — список с поиском, редактор:
- код и QR: генерация уникального кода, предпросмотр, скачивание PNG с «тихой зоной», полноэкранный показ;
- тип и содержимое, загрузка медиа в Storage (`content-media`) или ручной URL;
- воспроизведение once/unlimited, `module_scope`;
- условие разблокировки, `requires_previous`;
- ветвление (до 8 вариантов).

**Вкладка «Персонажи»** — имя, код бейджа с QR (PNG `BADGE-<код>.png`), пароль, таймеры сессии и бездействия, доступные модули, активность.

**Вкладка «Модули»** — название, код доступа, таймер тишины, флаг «мастерский терминал». Для существующего модуля дополнительно:
- текущее состояние (связь, текущий контент, последняя запись журнала), сброс контента;
- список персонажей модуля;
- тревоги модуля с действиями «снять с этого модуля» и «снять везде».

Удаление модуля запрещено, пока на него ссылаются контент, персонажи, тревоги, журнал или логи.

**Не реализовано:** вход мастера, отправка `events`, просмотр журналов модулей в реальном времени, выгрузка логов.

Текст «код вводится вручную на терминале» в редакторе модуля не соответствует терминалу: модуль задаётся адресом страницы (§2), отдельного поля ввода нет.

## 10. Медиа и хранилище

- **Заранее подготовленные медиа** могут лежать:
  (а) в репозитории GitHub Pages в папке `media/` — тогда `media_url` относительный, например `media/briefing.mp3`; лимит 100 МБ на файл;
  (б) в Supabase Storage, bucket `content-media` (публичный), загружаются кнопкой в админке. Путь: `<тип>/<код>-<timestamp>.<расширение>`.
- Тяжёлое видео лучше хранить в Storage. Бесплатный тариф Supabase — 1 ГБ хранилища, следите за объёмом.
- Голосовые записи журнала (будущее) — через Storage.
- Офлайн-режима нет: без интернета терминал не работает (Supabase + CDN-библиотеки). PWA / service worker — следующий этап.
- Шифрование не требуется («играем на честность»), с оговорками §15.

## 15. Безопасность при публичном размещении

Публичный ключ Supabase вшит в HTML, RLS настроен как «allow all for anon». Для локальной сети это было приемлемо. После публикации на GitHub Pages адрес и ключ доступны **всему интернету**: любой может читать пароли персонажей и весь сюжетный контент, а также менять или удалять данные.

Минимум для ближайшей игры:
- панель мастера запускается только локально, в публичный репозиторий не кладётся;
- перед игрой — резервная выгрузка таблиц;
- после игры — отключить Pages или сменить ключ.

Целевое решение (п. 2 в §14):
- мастер входит через Supabase Auth, роль хранится в `admins`;
- anon разрешено: чтение `modules`, `alerts`, `content_items` (по `trigger_code`), запись в `journal_entries`, `logs`, `character_progress`, обновление `modules.last_seen_at`;
- проверку пароля персонажа перенести в RPC-функцию Postgres, чтобы колонка `password` не читалась клиентом;
- изменение `characters`, `content_items`, `alerts`, `modules` — только для авторизованного мастера.

## Приложение А. Схема базы данных

Базовая схема — как в v2 (`game_sessions`, `modules`, `characters`, `content_items`, `character_progress`, `events`, `journal_entries`, `logs`, `admins`, `alerts`). Ниже — **миграции v3**, которые обязательны для текущего кода:

```sql
-- Тип контента image
alter table content_items drop constraint if exists content_items_type_check;
alter table content_items add constraint content_items_type_check
  check (type in ('text','image','audio','video','event'));

-- Снятие глобальной тревоги с отдельного модуля
alter table alerts add column if not exists excluded_module_ids uuid[] default '{}';

-- Хранилище медиа для админки
insert into storage.buckets (id, name, public)
values ('content-media', 'content-media', true)
on conflict (id) do update set public = true;

create policy "anon read content-media"   on storage.objects for select to anon using (bucket_id = 'content-media');
create policy "anon insert content-media" on storage.objects for insert to anon with check (bucket_id = 'content-media');
create policy "anon update content-media" on storage.objects for update to anon using (bucket_id = 'content-media');
```

Для `upsert` при загрузке файла Storage требует политики на select, insert и update — поэтому все три.

**RLS:** на всех таблицах политика «allow all for anon» (см. §15 о рисках).

**Realtime** (Database → Publications → supabase_realtime): `alerts`, `modules`, `journal_entries`, `events`.

Неиспользуемые сейчас поля и таблицы: `game_sessions`, `admins`, `events`, `content_items.chain_id` / `order_index` / `created_by`, `character_progress.choice_made`, `modules.status`, `journal_entries.synced`.

## Приложение Б. Развёртывание

**Основной вариант — GitHub Pages.** Пошаговая инструкция — в отдельном файле `DEPLOY_github_pages.md`. Кратко:
1. Публичный репозиторий: `index.html` (терминал), `fonts/`, `.nojekyll`, по желанию `media/`.
2. Settings → Pages → Deploy from a branch → `main` / root.
3. Каждый терминал открывает `https://<логин>.github.io/<репо>/?module=<access_code>`.
4. Панель мастера — локально: `python3 -m http.server`, затем `http://localhost:8000/terminal_admin_6_6.html`.

**Практические заметки:**
- HTTPS-адрес Pages снимает проблему с камерой на устройствах в локальной сети и с `file://`.
- Пути на Pages чувствительны к регистру; имена файлов в `fonts/` должны точно совпадать с указанными в CSS.
- Pages кэширует страницу до ~10 минут. После обновления — Ctrl+Shift+R.
- Supabase засыпает примерно через 7 дней без обращений — перед игрой разбудить.
- Фоновые вкладки браузер притормаживает: держите терминал на переднем плане, отключите сон экрана.
- Демо-данные: персонажи `CHAR-001` / `CHAR-002` (пароль у второго — `1234`), объекты `ITEM-LOG-01`, `ITEM-VIDEO-01`, `ITEM-AUDIO-01`, `ITEM-CHAIN-01`. Тестовая тревога — кнопкой в панели мастера.

## Приложение В. Состав кода

**`index.html` / `terminal_full_paradise.html`:**
- 3D-сцена купола (three.js) и декоративная телеметрия (`tuiDrift`, `tuiSpark`, `tuiEq`);
- `DB` — доступ к Supabase: модуль, персонажи, контент, журнал, логи, прогресс, пульс, поиск контента для тишины;
- `AlertManager` — тревоги (опрос + realtime, учёт `excluded_module_ids`);
- `SilenceWatcher` — автотриггер тишины в эфире;
- `App` — авторизация, таймеры, сканер, журнал, контент и условия разблокировки;
- автоподгонка плотности колонок.

**`terminal_admin_6_6.html`:**
- `Templates` — шаблоны тревог в `localStorage`;
- `Admin` — вкладки «События», «Контент», «Персонажи», «Модули», загрузка медиа, генерация QR;
- обработка кнопок через `data-action` (без inline-обработчиков).

Устаревшие ссылки в комментариях кода (`terminal_full_5_6.html`, `terminal_admin_6.html`, `terminal_kolonista_MVP.html`) указывают на предыдущие версии файлов.
